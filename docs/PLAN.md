# Marathon — Execution Plan

**Status:** Phase 1 exit criterion met 2026-08-18 (position-shifted KV reuse in vLLM: edit-turn prefill 6.1× faster, output byte-identical); multi-span/moved-block reuse and a 144-session distribution eval done 2026-08-19; see findings.md, consolidated in [phase1-report.md](phase1-report.md) · **Updated:** 2026-08-19 · **Companion:** [DESIGN.md](../DESIGN.md) (doc 0001), [protocol.md](protocol.md), [findings.md](findings.md), [phase3-design.md](phase3-design.md)

This plan sequences the delta-encoded context architecture from pure systems work (buildable today against existing APIs) toward the research bet (training the trust contract). Each phase has explicit exit criteria; a phase is not done until its metrics are collected and its correctness gate passes.

## Phase 0 — Deterministic core and prefix-cache maximization *(done)*

Build the ledger, diff engine, and turn protocol; use them to canonicalize state so unchanged history always serializes byte-identically and append-only, making provider prefix caching hit maximally. No custom model, no self-hosted inference.

Delivered so far: canonical serialization with the append-only prefix guarantee, hash-chained ledger with tamper detection, rsync-style block delta engine with randomized round-trip property tests, turn protocol with integrity verification (reconstruction is proven against the target hash, never assumed), offline benchmark harness, experimental live TTFT/cache probe, CI (lint + tests on 3.10 and 3.12).

Done 2026-08-18: live probe run against the Anthropic API (cache-read = full history on unchanged-prefix turns; one early edit collapses it — see [findings.md](findings.md)); session runner (`session.py`) with the canonical serializer as the single path to the wire; full-context replay correctness gate in CI (`tests/test_replay_gate.py`); baseline metrics published in README and findings.md. Still open: TTFT flat-vs-growing needs longer sessions than the probe has run; single-writer concurrency and store eviction are tracked under cross-cutting.

**Exit criteria (met 2026-08-18):** wire bytes per turn ~O(|diff| + |input|) in the offline bench; live probe shows cache-read tokens ≈ total history tokens on unchanged-prefix turns; correctness replay gate green in CI.

## Phase 1 — Self-hosted inference and warm-tier KV reuse *(current)*

Started 2026-08-18. Stack: WSL2 Ubuntu on the RTX 5090, `~/marathon-venv` with torch 2.13+cu130, vLLM 0.27.1, LMCache 0.5.3, model `Qwen/Qwen3-14B-FP8` (dense full-attention on purpose — hybrid Gated-DeltaNet models like Qwen3.5/3.8 carry recurrent state with no per-token KV on most layers, so non-prefix KV reuse can't be shown on them; that degradation is a Phase 1.5 question). Reproducible via `scripts/phase1_setup.sh`; probes via `scripts/phase1_probe.sh` → `marathon.local_probe` with modes `none` / `prefix` / `blend`. Local prefix-cache baseline measured (edit-turn collapse: 0.12 s → 1.29 s prefill), CacheBlend now runs fully native, and the route is closed: on the edit turn it ties full recompute at every recompute ratio (0.15/0.05/0.02), it stays 4–5× behind prefix caching on unchanged turns, and blend + prefix caching together crashes inside LMCache. Marathon's own position-shifted KV reuse is the route that works: `kvshift.py` (HF prototype) showed re-rotating cached keys by the edit's token offset δ (RoPE is a rotation, so the shift is exact) and recomputing only the edited span + new query keeps KL vs full recompute ≈0.002 with all planted facts exact at 0.7–9% of tokens forwarded; `vllm_shift_connector.py` (`--mode shift`) puts that inside vLLM 0.27 as a KV connector — on Qwen3-14B-FP8 the edit turn drops from 1.465 s to 0.242 s (6.1×), unchanged turns keep the 0.13 s prefix-cache path, and every turn's output is byte-identical to prefix mode. Since confirmed (findings.md, 2026-08-18/19): mid-history edit 4.7×, +186-token grow edit 5.9×; multi-span edits cost +66 ms per edited message in vLLM (k=1 6.3×, k=2 4.5×, k=4 3.0×, k=8 1.9×; break-even ≈17 edited messages), moved blocks are recomputed rather than transplanted (transplanting KV that summarised a different prefix produces garbage; a pure move still gets 4.0×); a 144-session Qwen3-8B eval (5 edit kinds, 7 query types) shows re-rotated reuse forwards 1.5–1.6% of tokens for median KL 0.003 vs prefix caching's 66–68% — the only failure class is edits to *governing* spans (system prompt / standing instructions; ~9× KL, independent of position or downstream size), which `reuse_plan` flags for repair. North-star measured 2026-08-19: edit-turn TTFT 0.15→0.26 s from 4k to 30k of history while prefix caching goes 0.42→3.94 s (15.1× at 30k), with the shifted copy on a fused Triton kernel at 1.43 TB/s; connector is session-keyed with LRU eviction and two-session isolation verified. Open: TP/preemption/chunked-prefill interactions untested; Phase 2.

## Phase 1.5 — Hybrid (linear-attention) models *(answered 2026-08-19, HF prototype)*

Measured on `Qwen/Qwen3.5-4B` (24 Gated-DeltaNet layers / 8 full attention, partial rotary + mRoPE) via `kvshift_hybrid.py` and `scripts/kvshift_hybrid.sh`. Re-rotation is still exact on the 8 attention layers (max abs error 1e-5 through the model's own rotary module, rotating only the 64 rotary dims). The other 24 layers have no per-token KV, so reuse becomes replay: cache each linear layer's own post-conv `(q, k, v, beta, g)` for the unchanged suffix — its true KV analogue — and roll only the recurrence, at 1.39% of a token-forward per replayed token. Result: the edit turn costs **1.5–2.2% of full-recompute FLOPs** at klmean 0.0017–0.0020 on planted facts, i.e. the dense win transfers on the compute axis — but it needs **~18x the cache bytes per token** (566 KB vs 32 KB), a fused scan kernel before wall clock follows the FLOPs (this prototype only gets 1.2–1.6x, on transformers' pure-torch fp32 chunk scan), and a new repair: an edit far from the end of a long context gets washed out of the decaying recurrent state, and recomputing the first ~256 tokens of the suffix fixes it. Reusing only the end-of-context state (what a serving system does by default) is 5–25x worse in KL. See findings.md.

**Open:** no distribution eval (three scenarios, single runs); M in first-M uncalibrated; nothing of this is in a serving engine.

Original plan text: stand up vLLM with LMCache to move beyond the prefix restriction: store KV for reused text segments regardless of position and recombine with selective recomputation (CacheBlend-style blending). The delta wire format from Phase 0 becomes the input that decides which KV segments are reusable.

**Exit criteria (met 2026-08-18, see findings.md):** measured TTFT improvement on mid-edit sessions (where prefix caching alone fails) versus the Phase 0 baseline — 6.1× on the edit turn; correctness replay gate still green and output parity byte-identical; memory budget for hot KV: 164 KB/token on Qwen3-14B (40 layers × 8 KV heads × 128 × 2 × bf16), 2.7 GB for the 16k-token store buffer.

## Phase 2 — Cold tier and recall-on-miss *(current, started 2026-08-19)*

Add the lossy tier: deep history demoted to embeddings/summaries with a paging policy, and recall-on-miss promotion back into the active window when a diff or query touches demoted content. The ledger's content addressing makes promotion exact — cold content is a pointer to verifiable bytes, not a paraphrase.

Delivered 2026-08-19: `marathon.cold` — a paging policy over a `Session` that keeps the model-facing active view under an `--active-window N` token budget by demoting the oldest non-governing messages (never the system prompt, never a `governing` span, never the last K turns) to a deterministic stub line carrying the message's own content address, `[cold #12 3f9a1c04: <first ~12 words>]`. The view is a pure function of `(messages, demoted, evicted)`, so hashes, replay and the reuse plan stay exact — and because only *content* changes, a demotion is an ordinary shrink edit and a promotion an ordinary grow edit, which is exactly the shape position-shifted KV reuse already prices cheaply. Stubs alone are still O(n), so the oldest stubs are *evicted* from the view once the budget is blown; the bytes stay in the ledger and the retriever still searches them, which is what makes the window genuinely bounded rather than merely 20x smaller. Recall-on-miss has both triggers: **exact** (the turn's delta touches a demoted message, detected by canonical byte comparison) and **query** (mean-pooled `all-MiniLM-L6-v2` on CPU, top-k≤2 above a cosine threshold), with every promotion and demotion logged with a reason. Wired into `MarathonServer` so paging flows through the same verified-state + reuse-plan + shift-connector path; `marathon.cold_eval` + `scripts/cold_eval.sh` run the eval. See [protocol.md](protocol.md) "Cold tier" and findings.md.

**Exit criteria:** bounded active-window size on unbounded sessions; recall-on-miss correctly restores demoted content in an eval of targeted questions about old context; quantified quality delta versus full-context replay stays within the agreed tolerance.

## Phase 3 — Robustness to stitched caches (research bet) *(reframed 2026-08-19; 8B result: mechanism real, gates not met)*

**The original bet is largely superseded by Phase 1.** Phase 3 was written as "fine-tune the model to consume delta-formatted *text* and trust that absence-from-diff means unchanged". Position-shifted KV reuse gets that outcome without training and more completely: the baseline is never retransmitted, re-tokenized or re-prefilled, but the model's attention still runs over the full history, so its input distribution never changes and there is nothing to persuade it of. Measured, not asserted — 1.5–1.6% of tokens forwarded for median KL 0.003 and planted-fact retrieval 105/111 vs full recompute's 106/111 over 144 sessions. A text-level delta format would have been strictly worse on both axes.

**What remains is the harder form of the same idea**, and Phase 1 handed us a sharp instance. (a) The one residual failure class: an edit to a **governing** span (system prompt, standing instruction, persona, output format) leaves the reused suffix `S` still conditioned on the instruction that is no longer there — ~9× KL, the only class with items over KL 0.2, independent of edit position and of |S| (the 2×2 at seed 1235 settles it: flipping the flag moves KL 9×, moving the edit moves it by nothing). Selective recompute does not fix it: `first-32` cuts dep-instruction first-token KL 0.3492 → 0.0384 and `first-512` (10% of `S`) → 0.0177 while restoring agreement in only half the cases, and `blend-r0.30` is *worse* than reuse-all because its layer-1 K-deviation selector barely registers an instruction flip. The contamination is diffuse across the suffix, not a prefix of it. (b) The general case: the same shape recurs in relocated blocks (a δ = −10,153 transplant produces garbage; `--repair-first 256` does not help, so relocations are recomputed), in large δ (spearman(KL, |δ|) = +0.237 overall, +0.407 among non-governing — the strongest continuous predictor in the eval), and in the hybrid tier's washed-out recurrent state. In every case today's answer is "recompute more"; the bet is that a small adapter buys some of it back, so reuse can be applied where a conservative planner must refuse it.

**Method: stitched-KV consistency fine-tuning** (`src/marathon/stitch_train.py`, designed in [phase3-design.md](phase3-design.md)). LoRA on q/k/v/o, forward passes run *with the stitched cache* (P verbatim, E′ fresh, S re-rotated), loss = KL to the frozen base model's full-recompute next-token distribution over the continuation — self-distillation where the teacher is the model's own clean-context behaviour, and the loss is literally `kvshift_eval`'s reported `klmean`. An anchor term runs the student on a *clean* cache against the same teacher; it is 0 for the base model by construction, so it reads out adapter-induced damage in the same units. Data is `kvshift_eval`'s own builders on fresh seeds, half governing edits and half other kinds for regularisation, with held-out seeds for eval. RoPE re-rotation is a fixed rotation and the scatter is a copy, so stitched attention is differentiable end to end; the reused KV is a constant (nothing can backprop into a previous turn), which is what keeps it cheap — gradients flow only through the fresh span's and the query's forward.

**Exit criteria** (held out; same metric as the 144-session eval): governing/non-governing mean KL ratio ≤ 2×, down from ~9×, with the median ratio (~3–4.5×) no worse, with no held-out governing item over KL 0.2; clean-context KL of the adapted model vs the base ≤ 0.002 (the `prefix-equiv` noise floor) and clean planted-fact accuracy unchanged within one item; no regression on the 144-session eval (non-governing klmean no worse than the seed-to-seed spread, ~20%, and no increase in items over KL 0.05); `kvshift_probe --scenario dep-instruction` first-token KL down from 0.3492 toward the `first-512` level at reuse-all's 0.4% recompute; and no change in tokens forwarded, since the adapter changes weights, not the reuse plan. Failing the clean-context or regression gate is a failure regardless of the governing result — efficiency that changes answers is a regression, not a win. Payoff if met: `reuse_plan` downgrades governing edits from `repair` to `reuse`, i.e. 1.5% instead of 68% of tokens forwarded on exactly the edit that invalidates the most history.

**8B result 2026-08-19: the mechanism is real and the gates are not met.** On 60 held-out sessions (Qwen3-8B, 4-8k tokens, LoRA r=16 on q/k/v/o, 200 training items, lr 3e-5) the adapter cuts governing-edit KL by **43% on the mean (0.0372 -> 0.0211) and 61% at p95 (0.2344 -> 0.0905)**, halving both the items over KL 0.05 (4 -> 2) and those over 0.2 (2 -> 1), with the two worst items in the run improving substantially. The governing/non-governing mean ratio falls 7.25x -> 3.01x. But non-governing edits get 37% worse (0.0051 -> 0.0070), clean-context drift is 0.0024 against a 0.002 budget, and one item still sits at 0.278 - so criteria 1, 2 and 3 fail while 4 and 5 pass. Verdict: **promising, not shippable** - the tail on the one class that forces full recompute is trainable, but not yet without taxing the 191/269 cases the governing flag deliberately leaves alone. Notably this used only the cheap half of the method (`--grad-prefill` off, so the model never learned what to *write* into `E'`), which is the first thing to try next, along with an explicit stitched-KV regularisation term on non-governing items. See [findings.md](findings.md).

**Earlier pilot 2026-08-19 (Qwen3-0.6B): negative, and the negative was about the testbed.** The held-out population did not reproduce the failure class — governing/non-governing mean KL ratio 1.50× against the 8B eval's ~9×, zero of 120 items over KL 0.05, `dep-instruction` at klmean 0.0038 instead of breaking — so the adapter had no signal to exploit: stitched KL 0.0028 → 0.0033 (no improvement) for 0.0031 of clean-context drift, failing the clean-context and no-regression gates. Causes: 0.6B follows standing instructions too weakly to be disturbed by a stale one, 3–5k sessions instead of 4–8k, and a harness defect that asked only the `fact-at` query. The instrument itself checks out (differentiable stitch identical to the serving path, gradients reaching the adapter, anchor exactly 0 at identity). Next: Qwen3-8B at 4–8k with the full query pool, base-only eval first to confirm the ~9× before training. See [findings.md](findings.md).

**Still deferred from the original text:** red-teaming baseline poisoning. A trusted substrate is a high-value target whether the trust is a training objective or a cache lookup, and the KV path arguably makes it worse — poisoned KV is not even inspectable as text. That belongs with the cross-cutting integrity work below.

## Cross-cutting: integrity and operations (never deferred)

Content addressing and hash-chain verification shipped in Phase 0 by design — a trusted substrate is a high-value target, and the model will treat poisoned baselines as settled truth. Single-writer-per-session concurrency and store eviction landed in the KV layer on 2026-08-19: the shift connector's store is keyed by session id with a token budget and LRU eviction across sessions, one in-flight writer per session is enforced rather than assumed, and the scheduler side declines a load whose source positions were evicted (a miss is a recompute, never a wrong answer) — see the "Connector" section of [protocol.md](protocol.md) for what that does *not* yet cover (tensor parallelism, preemption, chunked prefill interleaved with a load). Still ahead: signed snapshots, the same TTL/eviction story for the *baseline* store rather than the KV store, and observability (per-turn metrics exported, not just printed). Every phase keeps the same regression rule: efficiency that changes answers is a regression, not a win.

## North-star metrics

Per-turn prefill tokens → O(|diff| + |input|). TTFT flat as session length grows. Correctness vs full-context replay within tolerance. Cost per turn flat as session length grows.
